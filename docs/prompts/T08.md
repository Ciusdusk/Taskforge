## 复用现有契约

- Job 与 Attempt 是不可变快照；策略来自 Job，不读取新注册默认值。
  成功领取已消耗一次预算，max_retries=N 最多 N+1 次尝试。
- SQLiteStore.claim_next() -> AttemptClaim | None；commit 成功才可执行。
  job_id + number 为完成凭据，遗留 RUNNING 当前不会被领取。
- Executor(registry).execute(claim) -> AttemptOutcome；执行一次、重校验参数、
  按 Job.timeout_seconds 单调计时；不写数据库、不决策重试。
  用户 TimeoutError 为 TASK_ERROR，框架计时器才产生 TIMEOUT。
  外部取消等待用户协程真正退出再传播 CancelledError，不自行生成 INTERRUPTED 结果。
  重复取消不得打断用户清理；用户忽略取消时继续等待。
- policy.decide_completion(job, outcome) 返回不可变 CompletionDecision；
  SUCCESS 直接成功，CONFIG_ERROR 直接失败，TASK_ERROR/TIMEOUT 按预算重试。
  policy.retry_delay_seconds(job) 为 min(cap, base × 2^(k−1))，无抖动，安全处理大次数。
  当前 INTERRUPTED 不自动重试；T08 按架构补充中断决策，保持业务失败规则。
- finish_attempt(job_id, number, outcome, *, status, next_run_at=None,
  retry_delay_seconds=None) -> Job；绝对时间与相对延迟互斥。
  相对延迟以完成事务时间为基准，向上取整到微秒，超出日期范围封顶为 UTC datetime.max。
  RETRY_WAIT 仍须有预算且时间严格晚于完成时间；存储校验并原子保存 Attempt 与 Job。
  成功清空当前摘要，失败历史、Job ID、参数、策略与首次 started_at 保留。
- Worker(store, registry, config=None) 使用调用方已初始化且仍打开的存储，实例只 run 一次。
  WorkerConfig(concurrency=4, poll_interval_seconds=1.0) 不可变且严格校验。
  固定异步槽位覆盖领取、执行、完成 commit；领取串行，用户执行期间无数据库会话。
  重试等待释放槽位，由轮询领取到期 Job，不在内存 sleep 保存计划。
- request_stop 当前停止新领取并唤醒空闲槽位，已开始的领取、执行和完成写入继续结束。
  数据库故障、不确定结果及 ExecutorError 停止领取，其他已启动槽位继续完成后传播原异常。
  外部取消 run 当前仅停止领取并等待，不主动取消用户函数。
- WorkerLock 使用规范化数据库路径加 .lock、fcntl.flock 非阻塞独占锁；
  描述符保持整个生命周期，关闭但不删除锁文件，第二个 Worker 不得进入领取或恢复。
- ClaimUncertainError / CompletionUncertainError 携带凭据，调用方查询确认；
  不执行不确定领取、不重交不确定完成、不重新执行用户函数。
  ExecutorError 属于框架故障，不能转换成业务失败或当场重试。
- db.py begin hook 唯一发出 BEGIN / BEGIN IMMEDIATE；_commit 故障使连接失效。
  不改动已验证的事务清理语义。JSONFormatter 与执行上下文已提供，
  不默认记录参数、完整 stdout/stderr。

## T08 实现范围

以 docs/architecture.md 为准：

- 获取独占锁并验证 schema 后，先完成遗留恢复，再开始正常领取。
  只有取得锁后才能认定旧 Worker 已退出。
- 遗留 RUNNING Attempt 标记 INTERRUPTED，并在同一短事务按剩余预算将 Job
  转为 RETRY_WAIT 或 FAILED。领取已经消耗预算，恢复不另增次数、不新建 Attempt。
  有预算从确认中断的事务时间计算退避，复用策略快照与纯函数边界。
- 恢复逐 Job 原子提交；恢复再次中断时，已提交记录不再 RUNNING，未提交记录下次继续恢复。
  保留原等待任务的 next_run_at，终态任务不自动重启。
- 停机先停止领取、等待运行任务，宽限期后请求协作取消。
  为宽限期增加实际需要的配置并严格校验，说明默认值；不新增硬超时机制。
- 用户协程真正结束后才保存中断、释放槽位。重复取消不能打断清理；
  用户忽略取消时报告停机未完成并继续持锁，不能提前记录完成或返回成功停机。
  已开始的领取及完成 commit 保持明确性与不确定结果语义。
- 延续 T07 锁、并发、有限重试、快照、错误分类与数据库故障契约。
  不实现 CLI、多 Worker、租约、心跳、人工重放或恰好执行一次保证。

## 必须验证

使用真实 SQLite 文件、async 用户函数、事件/屏障与必要子进程：

- 正常停机、宽限期内完成、超过宽限期后的协作取消和清理；
  用户不响应取消及重复取消时，槽位、锁和历史不得提前释放或伪造。
- 真实 Worker 子进程被强制退出，下一进程可取得同一锁并恢复 RUNNING；
  按预算保存 INTERRUPTED 和重试时间，次数、身份、首次开始时间及历史准确。
- 预算耗尽转 FAILED；恢复再崩溃可继续，已恢复 Job 不重复中断，跨表状态始终原子。
- 未到期 RETRY_WAIT 保留原时间，终态不重启，配置错误不重试。
- 恢复、领取及完成的 SQL/commit 故障、取消与不确定结果保持原异常链和可查询凭据；
  不执行不确定领取，不自动重交完成结果。
- 锁先于恢复、第二个 Worker 不进入数据库恢复；并发、JSON 身份及 T01—T07 不回归。
- 外部副作用完成但成功 commit 前崩溃的重复执行风险有真实证据和文档说明。
- 清理全部测试协程、子进程和临时文件，不改依赖、uv.lock 或历史 T01 收据，不加占位测试。
