## 复用现有契约

- TaskRegistry.get(name) 返回 TaskDefinition；策略来自不可变 Job 快照。
- SQLiteStore.claim_next() -> AttemptClaim | None；commit 成功才可执行。
  job_id + number 为完成凭据；成功领取已消耗一次尝试预算。
- Executor(registry).execute(claim) -> AttemptOutcome；执行一次、重校验参数、
  按 Job.timeout_seconds 单调计时；不写数据库、不决策重试。
- SUCCESS 无错误；FAILED 使用 TASK_ERROR / TIMEOUT / CONFIG_ERROR。
  ExecutorError 属于框架故障，保留异常链，不能转为业务失败或自动重试。
- finish_attempt(job_id, number, outcome, *, status, next_run_at=None) -> Job；
  RETRY_WAIT 必须仍有预算且 next_run_at 带时区并严格晚于完成事务时间。
  Worker 决策，存储校验并原子保存 Attempt 与 Job。
- Worker(store, registry, config=None) 使用调用方拥有且已初始化的存储，实例只 run 一次。
  WorkerConfig(concurrency=4, poll_interval_seconds=1.0) 不可变并严格校验。
  固定异步槽位覆盖领取、执行、完成 commit；领取串行，执行期间没有数据库会话。
  T06 当前 SUCCESS 写成功，普通 FAILED 写最终失败，即使有重试预算也不重试。
- request_stop 停止新领取并唤醒空闲槽位；已开始的领取、执行和写入继续结束。
  数据库故障、不确定结果及 ExecutorError 停止新领取，其他已启动槽位继续完成，
  最后传播原异常。外部取消 run 同样等待已启动工作，不主动取消用户函数。
- WorkerLock 使用规范化数据库路径加 .lock、fcntl.flock 非阻塞独占锁；
  描述符保持整个生命周期，关闭但不删除锁文件；第二个 Worker 不得进入领取。
- ClaimUncertainError / CompletionUncertainError 携带凭据，调用方查询确认；
  不执行不确定领取、不重交不确定完成、不重新执行用户函数。
- db.py begin hook 唯一发出 BEGIN / BEGIN IMMEDIATE；_commit 故障使连接失效。
  不改动已验证的存储事务清理语义。
- JSONFormatter 与不可变执行上下文已提供；不默认记录参数、完整 stdout/stderr。
- T08 前遗留 RUNNING 尝试不自动恢复或重新领取；本任务不实现恢复、中断或停机宽限期。

## T07 实现范围

以 docs/architecture.md 为准，增加实际需要的 policy.py，并将 Worker 的完成决策接入：

- 第 k 次失败后的等待为 min(cap, base × 2^(k−1))，首期不加抖动。
  max_retries=N 最多 N+1 次尝试；使用 Job 快照，不读取新注册默认值。
- TASK_ERROR 和 TIMEOUT 有预算时写 RETRY_WAIT 与持久 next_run_at，无预算写 FAILED。
  CONFIG_ERROR 直接 FAILED；成功直接 SUCCESS，不生成重试。
- 重试与状态决策使用清晰的纯函数边界；注意大次数的指数计算与有限数值约束。
- Worker 不用长时间内存 sleep 保存重试计划；完成后释放槽位，由既有轮询领取到期 Job。
- 每次重试保留 Job ID、首次 started_at、参数与策略快照，增加新的 Attempt；
  成功清空当前错误摘要但保留此前失败历史。
- 延续 T06 锁、并发、停止和数据库故障语义；不重试框架/存储故障。
  不实现 CLI、崩溃恢复、多 Worker、租约、硬超时或人工重放。

## 必须验证

使用真实 SQLite 文件、async 用户函数、事件/屏障与必要子进程：

- max_retries=0、N 次额外重试、预算耗尽；成功不重试，配置错误不重试。
- TASK_ERROR、用户 TimeoutError、框架 TIMEOUT 的决策与历史准确。
- 精确验证退避指数、封顶、快照稳定及大次数处理；重试时间实际持久化。
- 到期前不会执行，边界到期可领取；Worker 重启仍遵循原 next_run_at，不提前执行。
- 重试等待释放槽位，其他任务继续执行，并发上限仍覆盖完成提交。
- 每次 Attempt 只执行一次；Job ID 稳定、首次开始时间保留、历史完整、成功清空当前错误。
- 领取/完成数据库故障、不确定 commit 和 ExecutorError 不触发重执行；
  锁、取消清理、JSON 身份及原有 T01—T06 行为不回归。
- 清理全部测试协程、子进程和临时文件；不改依赖、uv.lock 或历史 T01 收据，
  不添加占位测试。
