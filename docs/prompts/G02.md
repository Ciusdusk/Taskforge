## 2. G01 实际接口与约束

- config.py：GitHubConfig.load(path=None)、Source、Budgets、IssueFilter、RefreshInput。
  来源包含 source_id、kind、repository、scan_skills、issue_filter 和 budgets；拒绝未知字段。
  RefreshInput 有 refresh_id、state_directory、source、source_generation、operation。
  DEFAULT_POLICY 为核心 ExecutionPolicy，2 次额外重试、5/60 秒退避、300 秒单次超时。
- auth.py：await resolve_credential() -> Credential，token 不进入 repr 或持久输入。
  tests 全部使用假凭据；凭据缺失在提交前检查由 G04 编排。
- http.py：GitHubHTTP(store, credential, AttemptBudget(source.budgets), ...)，异步上下文关闭客户端。
  get(path_or_url) 返回 CachedResponse(etag, body, link)；paginate(path, list_field=None) 返回
  完整合并的 JSON 列表，可用 list_field="commits" 读取 Compare 列表。
  Compare 的 total_commits、status、base/merge-base 等元数据需用 get 明确核对；
  paginate 的列表返回值不替代数量与历史检查。新增必要分页接口时保留 G01 的行为契约。
- API 根地址固定 https://api.github.com，Accept 为 application/vnd.github+json。
  默认 per_page=100、10 页、100 次实际请求、500 条增量 Commit、累计冷却等待 30 秒。
  HTTP 分项超时为 connect/write/pool 5 秒、read 20 秒，总等待 30 秒包含门控、冷却和重定向。
  每个尝试复用同一个 AttemptBudget，重定向也计请求数。HTTP 不自动重试。
  缓存保存 GET URL、Accept、版本组成的完整非敏感键，以及 ETag、body、Link。
  第一页 304 仍访问后页；失败、分页不完整或预算中断抛业务错误，不返回部分完整结果。
- locking.py：InstanceLocks(directory).source(source_id) 是异步上下文，进程内互斥，
  跨进程来源 flock 非阻塞冲突；request_path 的等待门控由 HTTP 使用，所有来源共用。
  锁文件保留。来源锁覆盖读取、完整采集和提交，HTTP 上下文嵌套在来源锁内。
  数据库操作不被取消，HTTP 取消等待清理，gh 子进程取消后回收；重复取消不提前释放锁。
- storage.py：BusinessStore(directory, busy_timeout_ms=5000)，initialize() 显式建立 schema v1，
  数据库为 directory/business.sqlite。每次操作单独连接，短 BEGIN IMMEDIATE 写事务。
  register_source(source, rebaseline=False) 返回 SourceState(source, generation, checkpoint)；
  source_state(source_id, generation=None) 可读取当前或历史代次。
  预算调整保留检查点；身份/扫描/筛选变化须显式 rebaseline；旧代次拒绝覆盖当前检查点。
  entities(repository_id, kind)、release_ids(repository_id)、skill_snapshot(repository_id, commit_sha)
  提供后续采集所需历史读取；cache_get/cache_put、cooldown/extend_cooldown 服务 HTTP。
  save_intent/associate_job/record_attempt 为 G04 留下已有持久基础，不在本任务编排核心提交。
- models.py：BatchWrite(input, checkpoint, coverage, complete=True, entities, changes, snapshots,
  skill_changes, release_ids)；对应 Entity、Change、SkillSnapshot、SkillChange、ReleaseIdentity。
  await store.apply(batch) 同事务提交记录、版本、变化、清单、覆盖和检查点及完成标记；
  新提交返回 True，已有相同输入的完成批次返回 False，不同输入复用 refresh_id 明确拒绝。
  complete=False 拒绝。completed(refresh_id) 使用独立连接；commit 或其清理故障后先核对标记，
  无法核对抛 CommitUncertainError，不能直接重做。Issue updated_at 规范化 UTC，较旧值不覆盖。

G01 证明的是传输分页和持久化基础。仓库身份、Compare 数量、Release 覆盖、tree truncated
及跨收集器共同完整性必须由 G02 检查；不把 HTTP 200 或已构造 BatchWrite 当作业务完整。

## 4. 实现项目完整采集

采集逻辑独立于 TaskForge 任务包装，可接收明确输入和执行身份供后续 direct 复用。
同一来源持锁后先核对完成标记、来源代次和最新检查点。已完成批次不重新应用业务变化。
网络在事务外执行；任一部分失败不提交项目检查点。

1. 读取仓库元数据、远端仓库 ID、默认分支和固定目标 SHA。后续历史与技能树都引用该 SHA。
   仓库路径重定向核对远端 ID，身份变化不能沿用旧基线。
2. 初次最多保存 20 条 Commit，注明有限历史窗口且全部标为初始化。增量使用前次成功 SHA
   与目标 SHA 的 Compare，完整分页并核对数量、比较状态和身份。SHA 相同为无变化。
   分叉、回退、旧 SHA 不可比较或增量超过 500 条时保留旧检查点，诊断需要 rebaseline。
3. 每次完整分页 Release 身份。初次登记全部可见已发布 ID，仅保存 published_at、ID 降序
   最近最多 10 条完整内容；后续新增首次观察 ID，并持续核对所有已保存内容的编辑。
   初始窗口外旧 ID 只保存身份。包含 prerelease、排除 draft；空列表正常。
   保存接入计划全部字段及规范化指纹，不能假设 updated_at。已关注 ID 消失保留历史并诊断。
   区分“首次观察到”和“本周新发布”；分页失败不推进检查点。
4. 仅两个技能来源扫描固定目标原生 tree 的普通 SKILL.md。保存完整路径/blob SHA 清单；
   recursive tree 截断时逐子树遍历。任何子树仍不完整或超预算均失败，不能判断删除。
   子模块和符号链接不展开，覆盖说明记录边界。Compare 的 300 文件上限不能证明技能完整。
   前后快照产生新增、修改、删除；重命名为删除加新增，链接固定到对应提交。
5. Commit、Release、技能共同通过后，构造完整覆盖说明和同一 BatchWrite，一次原子提交。
   每次尝试固定目标，失败重试重新读最新检查点；预算共用，代次隔离且历史保留。

完成条件：上述各部分有真实临时 SQLite 与受控 API 的行为证据；没有部分推进检查点、
错误删除推断、旧代次覆盖或重试重复应用变化。
