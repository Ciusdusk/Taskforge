## 复用现有契约

- TaskRegistry 与 load_registry("module:attribute") 显式加载可信本地任务模块。
  提交先校验参数并存规范化 JSON；查询无需注册表，也不得导入任务模块。
- DatabaseConfig 规范化本地文件路径；SQLiteStore 是调用方管理生命周期的 async context
  manager，initialize 显式建表或校验 schema，查询不自动初始化或迁移数据库。
- TaskForge.submit/get/list/history 返回不可变快照；list 使用 (created_at, id) 升序分页，
  游标为排他边界。历史按 number 排序，无 Job 与已有 Job 的空历史须明确区分。
- Job 保存策略快照；领取 commit 成功才可执行，max_retries=N 总尝试上限 N+1。
  重试等待与中断恢复复用纯 policy 决策及完成事务时间；配置错误不重试。
- Worker(store, registry, config=None) 仅 run 一次；调用方先初始化并保持存储打开。
  启动顺序：取得 WorkerLock、验证 schema、逐 Job 原子恢复、正常领取。
  第二个 Worker 不进入数据库恢复；关闭但不删除规范化路径加 .lock 的锁文件。
- WorkerConfig(concurrency=4, poll_interval_seconds=1.0, shutdown_grace_seconds=30.0)
  不可变、严格校验；宽限期为有限非负数，0 立即请求协作取消，不是硬超时。
- request_stop 停止领取并唤醒空闲槽位，宽限期后取消执行器；用户协程真正退出且完成
  中断持久化才释放槽位和锁。重复取消不打断清理，忽略取消记录 shutdown_incomplete
  并继续等待、持锁。已开始的数据库操作不被停机取消。
- 外部取消 run 按同一停机流程等待后传播 CancelledError；用户自行取消保存 INTERRUPTED
  后停止领取并传播取消。Executor 不自行持久化中断，ExecutorError 不是业务失败。
- SubmissionUncertainError 携带 job_id；ClaimUncertainError/CompletionUncertainError
  携带 job_id、number。恢复也复用 CompletionUncertainError。须输出可查询凭据和
  明确失败退出码，不执行不确定领取、不重交不确定完成、不重新执行用户函数。
- SQL/commit 故障保留原异常链；db.py begin hook 唯一发出 BEGIN/BEGIN IMMEDIATE，
  _commit 故障使连接失效，不改已验证的事务清理语义。
- JSONFormatter 使用标准 logging，包含 time/level/event/job_id/attempt_number/error_kind；
  核心不配置 root logger，不默认输出参数或完整 stdout/stderr。
- 外部副作用完成但成功 commit 前崩溃可重复执行；真实子进程证据见 tests/test_recovery.py。
  不提供业务去重、人工重放或恰好执行一次保证。

## T09 实现范围

以 docs/architecture.md 为准，用现有 Typer 依赖实现 cli.py 与打包命令入口：

- init：显式初始化或校验数据库。
- submit：显式加载注册表、读取 JSON 输入并调用 Python 提交接口，输出稳定 Job ID。
- worker：显式加载注册表，管理存储与 Worker 生命周期；复用配置校验和恢复流程。
  处理 SIGINT/SIGTERM 并调用 request_stop，不能重复取消用户清理、提前关闭存储或释放锁。
  忽略取消时继续报告停机未完成，不能宣称成功退出。
- list/show/history：复用查询接口；无需任务模块即可查看状态、策略与尝试历史。
- 定义并文档化参数、输出格式与退出码；非法 JSON、输入校验、未知名称/ID、注册加载、
  schema、锁、存储与框架故障均明确报告。正常帮助及查询不触发用户函数执行。
- CLI 只编排核心接口，不复制持久化、重试、恢复、取消或锁实现。

不实现 T10 场景集、Cron、多 Worker、租约、心跳、Web UI、用户取消命令、人工重放或迁移框架。
