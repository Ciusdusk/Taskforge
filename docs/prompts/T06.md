## 复用现有契约

- TaskRegistry.get(name) 返回 TaskDefinition；执行策略来自 Job 快照。
- SQLiteStore.claim_next() -> AttemptClaim | None；只有 commit 成功才返回可执行领取。
  claim.job_id + claim.number 为完成凭据；凭据及 Job 不可变。
- Executor(registry).execute(claim) -> AttemptOutcome；再次校验参数、执行一次、
  按 Job.timeout_seconds 单调计时；不写数据库、不决策重试。
- SUCCESS 无错误；FAILED 使用 TASK_ERROR / TIMEOUT / CONFIG_ERROR。
  ExecutorError 是框架故障，保留异常链；日志用 EXECUTOR_ERROR，
  存储 ErrorKind 没有这一项，不转换为业务失败。
- 外部取消等待用户协程实际结束后传播 CancelledError；不返回 INTERRUPTED outcome。
  重复取消不会再次打断用户清理；超时清理期间的外部取消优先。
  不响应取消的用户协程会让执行接口一直等待；不可提前释放槽位或锁。
- finish_attempt(job_id, number, outcome, *, status, next_run_at=None) -> Job；
  Worker 选择 Job 状态。T06 只建立基础闭环，SUCCESS 保存成功，普通失败保存最终失败，
  不实现 T07 的重试决策与退避。
- ClaimUncertainError / CompletionUncertainError 携带凭据，查询确认；
  不能执行不确定领取，也不能因完成结果不确定而再次执行用户函数。
- 存储采用独立短会话；db.py begin hook 唯一发出 BEGIN / BEGIN IMMEDIATE，
  _commit 故障时 invalidate 连接。不要改动已验证的事务清理语义。
- JSONFormatter、get_execution_context 和不可变 ExecutionContext 已提供；
  不默认记录完整参数，不捕获完整 stdout/stderr。

## T06 实现范围

以 docs/architecture.md 为准，增加实际需要的 worker.py、locking.py 及必要配置与错误：

- Worker.run() 形成领取、单次执行、完成持久化闭环；Worker.request_stop() 停止新领取，
  为可控退出提供最小接口。完整停机宽限期、取消编排及崩溃恢复属于 T08。
- 使用 fcntl.flock 非阻塞独占锁，锁文件位于规范化数据库路径旁；
  Worker 生命周期保持描述符，退出关闭但不删除锁文件。
  同一数据库第二个 Worker 必须明确拒绝启动，其他数据库可独立运行。
- 有界异步并发与空队列轮询；槽位覆盖领取、用户执行、完成持久化全过程。
  无槽位不领取；用户执行期间不持有数据库会话。
- 单个业务失败或超时不终止其他任务；未知名称或参数不匹配保存配置失败。
- 数据库故障、结果不确定及 ExecutorError 停止新领取，保留异常链并输出可关联日志；
  不自动重交或重新执行，不伪造成功/业务失败。
- 退出前确保已启动用户协程实际结束才释放执行资源和锁。
  不实现 CLI、重试策略、恢复流程、多 Worker、租约或硬超时。
  在 T08 恢复实现之前，明确现有遗留 RUNNING 尝试的限制。

## 必须验证

使用真实 SQLite 文件、真实 async 用户函数、事件/屏障和必要子进程：

- 两个独立进程对同一数据库互斥；持锁期间失败方不能领取；
  退出释放后可再次获得锁，锁文件不删除；不同数据库独立。
- 实际重叠执行，最大并发严格有界；执行结束但完成 commit 尚未结束时槽位仍占用，
  包括用户 finally 尚未完成的超时情况。
- 成功、业务异常、用户 TimeoutError、框架超时、配置错误的状态与历史准确；
  单个业务失败隔离，函数只执行一次。
- 空队列不忙轮询，request_stop 后不再领取，正常退出等待运行中的任务与完成写入。
- 注入领取/完成数据库故障及 ExecutorError 后停止新领取；
  不确定结果不导致重新执行，保留可查询身份和异常链。
- JSON 日志关联 Job 和尝试，执行器/存储已有行为不回归；
  所有测试创建的协程与子进程都清理。
- 不改依赖、uv.lock 或历史 T01 收据，不增加占位测试。
