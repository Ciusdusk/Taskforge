## 复用 T02 契约

- 公共接口由 taskforge 导出 TaskRegistry、TaskDefinition、ExecutionPolicy、load_registry 及框架错误。
- registry.task(name, *, input_model, policy=None) 保留原 async 函数；registry.get(name) 获取定义。
- definition.validate_input(data) 校验 Python 输入；serialize_input(data) 返回已校验且可重新校验的
  JSON 对象字符串；validate_json(payload) 使用模型的 JSON 语义重新校验。
  保留 Pydantic ValidationError，无法序列化时抛出 InputSerializationError。
- 用户模型决定类型转换、严格模式及未知字段策略，不由框架改写配置。
- ExecutionPolicy 为不可变、独立注册快照；默认 max_retries=0、retry_base_seconds=1.0、
  retry_cap_seconds=60.0、timeout_seconds=300.0。提交时继续保存各字段的持久快照。
- 注册表显式按 module:attribute 加载，不进行全局扫描。查询不要求导入用户任务模块。

## T03 的实现范围

以 docs/architecture.md 为准，仅创建本任务需要的模块、模型和错误类型：

- 使用已确认的 SQLAlchemy 2.x 异步接口、aiosqlite 和本地 SQLite，实现 jobs、attempts 表、
  schema 显式初始化、版本记录与不兼容版本拒绝。落实已约定的列、外键、状态与次数范围、
  正超时、退避范围及索引约束，不新增依赖或更换架构。
- 实现 SQLiteStore 的提交与查询，以及 TaskForge 的异步 submit/get/list/history 接口。
  不暴露 ORM 对象；公共返回模型及参数提供完整类型注解，兼容 mypy strict。
  配置仅增加 T03 真正需要的数据库参数。
- 提交先按稳定名称查找任务、校验输入并生成规范化 JSON，再写入数据库。
  Job 使用 UUID4 字符串稳定 ID，初始 PENDING、attempt_count=0、next_run_at=created_at，
  开始、结束与错误字段为空。此阶段不创建执行尝试。
- 提交保存执行策略各字段的快照，后续注册默认值变更不影响已提交 Job。
  成功返回意味着事务已提交；结果不确定的提交错误携带 Job ID，供调用方查询确认。
- 查询无需加载任务模块；get/list/history 返回持久快照，list 遵守 (created_at, id) 稳定分页。
  明确未知 Job、无历史与分页参数错误的行为，记录最终接口及示例。
- 数据库时间保存 UTC epoch 微秒整数，对外使用带时区 datetime。
- 每次操作使用独立、短生命周期 AsyncSession；写操作显式统一 BEGIN IMMEDIATE，
  避免驱动和 SQLAlchemy 造成嵌套 BEGIN。外键生效、锁等待有上限、失败明确返回。
  提交失败回滚，不遗留半成品。

T03 不实现 claim_next、finish_attempt、Executor、Worker、重试调度、进程锁、崩溃恢复或 CLI。
T04 处理原子领取与完成；其他后续任务的模块不预建空实现。

## 必须验证的行为

使用真实临时 SQLite 文件验证：

- schema 初始化可复用；不兼容版本明确拒绝；实际表和约束符合架构。
- 合法提交产生符合初始状态与策略快照的持久 Job；参数 JSON 能用 T02 接口重新校验。
- 未知任务、非法输入、无法 JSON 序列化的输入不入库。
- 关闭存储后重新打开仍可查询；查询不依赖任务注册表或用户模块导入。
- 默认策略变更不影响已有记录；返回快照不泄露 ORM 会话或可变数据库内部状态。
- get/list/history 的未知 ID、空历史、稳定排序与分页边界符合最终记录的契约。
- 实际写入故障触发回滚；不确定提交错误的 Job ID 可用于查询确认。
- T02 行为不回归；保持依赖和锁文件，不增加占位测试。
