## T02 的实现范围

- 实现 TaskRegistry：装饰器注册、按稳定名称查找、参数校验，以及按 module:attribute 显式加载注册表。
- 任务为接收单个 Pydantic 输入模型的 async 函数，返回 None；装饰器保留原函数直接调用能力。
- TaskDefinition 保存名称、函数、输入模型与默认执行策略。仅建立 T02 真正需要的模型和错误类型。
- 校验注册声明：重复名称、同步函数、错误的输入模型或函数调用形态有明确错误；不同注册表互相隔离。
- 查找未知任务、导入失败、属性不存在或属性不是注册表，均有可解释的错误，不使用全局隐式扫描。
- 输入按显式模型校验，并提供 JSON 序列化与重新校验路径，供后续提交端和 Worker 复用。
  不可序列化的输入应有明确错误；类型转换及未知字段处理遵守模型声明，不悄悄改写用户模型配置。
- 执行策略至少包含 max_retries、retry_base_seconds、retry_cap_seconds、timeout_seconds。
  max_retries 默认 0；校验次数和时间范围，记录其余默认值及理由。这里只定义策略，不实现退避调度。
- 公共接口提供类型注解，兼容 mypy strict；保持模块接口简单。

T02 不访问数据库，不实现提交、领取、执行器、Worker、CLI、日志系统或崩溃恢复。
沿用已确认的单 Worker、SQLite、aiosqlite 设计，不新增依赖或重做架构。

## 必须验证的行为

- 注册后可按名称查找，原函数仍可直接 await。
- 重名、同步函数、未知任务及非法注册声明被拒绝，失败注册不破坏已有注册项。
- 合法与非法输入、模型声明的未知字段策略、JSON 往返得到预期结果。
- 非法执行策略被拒绝，不同任务的默认策略互不影响。
- 两个 TaskRegistry 没有共享注册状态。
- module:attribute 的成功加载和各类失败路径。
