## 复用契约

- TaskRegistry/load_registry 显式加载可信 module:attribute；本地模块通过 PYTHONPATH
  或安装进入搜索路径。提交先校验再保存规范化 JSON 与策略快照，查询不导入任务模块。
- SQLiteStore 由调用方管理生命周期，init/initialize 显式建表或校验，查询不迁移。
  list 按 (created_at, id) 升序分页，排他游标；已有 Job 空历史与未知 ID 明确区分。
- Worker 独占规范化数据库路径加 .lock，持锁验证 schema、逐 Job 恢复后才领取。
  max_retries=N 最多 N+1 次成功领取；重试与中断从完成事务时间计算，遵循持久到期时间。
- WorkerConfig 默认 concurrency=4、poll_interval_seconds=1、shutdown_grace_seconds=30；
  宽限期 0 是立即请求协作取消，用户真正退出并完成中断持久化才释放槽位和锁。
- SIGINT/SIGTERM 只 request_stop，重复信号不打断清理；忽略取消报告 shutdown_incomplete，
  继续等待与持锁，不宣称成功退出。已开始的数据库事务不受停机取消。
- CLI taskforge 提供 init/submit/worker/list/show/history；参数、JSON 输出与退出码以
  README 的 CLI 节和 tests/test_cli.py 为准。submit 输出一行 Job UUID，业务/配置失败
  由 show/history 查看，不直接使 Worker 非零退出；框架/存储/锁故障明确非零退出。
- 不确定提交/领取/完成退出码 9，输出 job_id 与可用 attempt_number；先查询确认，
  不执行不确定领取、不重交不确定完成、不重新执行用户函数。
- db.py begin hook 唯一开启 BEGIN/BEGIN IMMEDIATE；_commit 故障使连接失效，
  SQL/commit 错误保留异常链。CLI 不复制持久化、重试、恢复、取消或锁实现。
- 外部副作用完成但 SUCCESS commit 前崩溃可能重复执行，核心不保证恰好一次或业务去重。
