## 复用 T03 契约

- taskforge 导出 DatabaseConfig、SQLiteStore、TaskForge、Job/Attempt、状态枚举、JobCursor 和错误。
- SQLiteStore(config) 支持 async context manager、显式 initialize()/close()。
  schema 版本 1 使用 PRAGMA user_version；已有兼容数据库重开后可直接查询。
- TaskForge(store, registry=None) 的 submit(name, data) 需要注册表，查询不需要任务模块。
  SQLiteStore.submit(definition, data) 先校验与序列化，再写入带 UUID4 ID 的 PENDING Job。
  提交保存全部执行策略，初始次数为 0，不创建 Attempt。
- get 返回不可变 Job；list(limit=100, after=None) 返回 tuple[Job, ...]，按 (created_at, id)
  升序进行排他游标分页；limit 为 1—1000 整数。未知 Job 抛 UnknownJobError；
  history 按尝试序号返回 tuple[Attempt, ...]，存在但未领取时返回空元组。
- StorageError 保留底层异常；SchemaError 表示初始化或版本问题。
  commit 开始后结果无法确认时，SubmissionUncertainError 携带 job_id 供查询；
  commit 阶段取消也转为该错误，commit 前取消传播并回滚。
- 时间为 UTC epoch 微秒整数，对外为带时区 datetime；不要用浮点时间戳损失精度。
- 每次操作使用独立短 AsyncSession。db.py 禁用驱动隐式 BEGIN，并由 SQLAlchemy begin
  hook 根据 sqlite_immediate execution option 统一发出 BEGIN / BEGIN IMMEDIATE；
  storage.py 的 _session(write=True) 复用该约定，不再次手动 BEGIN 或混用事务开启方式。
- 复用 storage.py 的 _commit：commit 失败或取消时 invalidate 会话连接，
  避免 SQLite 残留事务回到连接池；不要只依赖 session.close()/rollback() 清理失败的 COMMIT。
- 每个连接启用外键，busy_timeout_ms 有限；错误摘要上限 2000、异常类型 256、traceback 16000
  个字符，约束由数据库执行。已有 jobs/attempts 状态、次数、预算、时间与索引约束须保持。

## T04 的实现范围

以 docs/architecture.md 为准，实现 SQLiteStore 的 claim_next、finish_attempt，
以及本任务真正需要的公共模型与错误。接口提供完整类型注解，返回不可变快照，不暴露 ORM。

- 领取在单个 BEGIN IMMEDIATE 事务中按 next_run_at、created_at、id 查找到期的等待 Job，
  条件更新再次检查状态和到期时间，变为 RUNNING、次数加一，并插入对应 RUNNING Attempt。
  首次领取设置 started_at；清空 next_run_at；提交成功后才返回可执行的领取凭据。
- 领取凭据明确携带 job_id + attempt number，空队列或未到期任务有明确返回契约。
- 完成在一个事务中验证 Job、尝试身份与运行状态，结束 Attempt 并更新 Job；
  过期、重复或不匹配的结果不得覆盖状态。成功清空当前错误摘要，保留历史错误。
- 保持 attempt_count 与历史数量一致，每个 Job 最多一个 RUNNING Attempt。
- 完成接口应支持架构要求的终态或重试等待更新，但本任务不实现 T07 的重试决策与调度。
  明确完成时间、错误摘要和历史字段的保存、长度处理及非法结果行为。
- 事务提交后才对调用者报告成功，失败回滚；明确领取/完成遇到数据库故障与结果不确定时的行为。
- 只增补真正必要的模块与模型，不预建后续模块，不更换架构或引入迁移框架。

不实现 Executor、Worker、重试决策、进程锁、恢复、日志系统或 CLI；不执行用户任务函数。

## 必须验证的行为

使用真实临时 SQLite 文件，以事件或屏障控制并发，不用固定长 sleep 同步：

- 多个独立连接并发领取同一 Job，只能成功一次；多个 Job 的领取无重复且顺序正确。
- 无任务、未到期任务、状态不符合或预算不符合的任务不会被领取。
- 领取后的 Job 状态、时间、计数与新 Attempt 同时可见，初始策略与参数快照保持不变。
- 成功/失败及接口支持的重试等待完成状态与尝试历史在同一事务内更新。
- 重复完成、过期尝试、错误 Job/序号、未知 ID、非法结果明确拒绝并保持已有记录。
- 真实 SQL 写入故障发生在事务中间时，领取与完成都完整回滚，不留下半成品。
- 重开后领取与完成状态仍可查询；返回对象为独立快照。
- T02/T03 行为不回归，依赖、锁文件与历史 T01 收据保持不变，不新增占位测试。
