## 复用现有契约

- TaskRegistry.get(name) 返回 TaskDefinition；validate_json(payload) 按用户模型重新校验
  持久 JSON，function 接收一个模型位置参数，返回 None。执行策略从 Job 快照读取。
- taskforge 已导出 AttemptClaim(job, number) 和 AttemptOutcome(status, error_kind=None,
  exception_type=None, error_message=None, traceback=None)，均为不可变 dataclass。
  claim.job_id + claim.number 为完成凭据；AttemptClaim 只在领取 commit 成功后返回。
- AttemptOutcome 为单次执行结果，不包含 Job 重试决策。SUCCESS 不带错误，
  FAILED 使用 TASK_ERROR / TIMEOUT / CONFIG_ERROR，INTERRUPTED 使用 INTERRUPTED。
  错误详情可空；finish_attempt 校验结果，并截断类型 256、摘要 2000、traceback 16000 字符。
  Executor 不写数据库、不计算重试、不领取或完成 Job。
- SQLiteStore.finish_attempt(job_id, number, outcome, *, status, next_run_at=None) 返回 Job。
  status 为 JobStatus.SUCCESS / FAILED / RETRY_WAIT；重试必须有预算、时间带时区且晚于完成时间，
  CONFIG_ERROR 不可重试。未来 Worker 与策略层决定最终 Job 状态。
- 存储操作使用独立短会话，db.py 的 begin hook 唯一负责 BEGIN / BEGIN IMMEDIATE；
  _commit 在失败或取消时使连接失效。不得改成重复 BEGIN 或仅关闭会话清理失败 COMMIT。
- ClaimUncertainError / CompletionUncertainError 携带 job_id 与 number；结果不确定时
  查询确认，不能直接执行不确定领取或重新执行用户函数。

## T05 的实现范围

以 docs/architecture.md 为准，增加真正需要的 executor.py、执行上下文与结构化日志能力：

- 提供完整类型注解的单次异步执行接口，读取领取的 Job 参数与 timeout_seconds 快照；
  查找任务定义并再次校验 JSON，再调用用户 async 函数。未知任务或参数不匹配返回 CONFIG_ERROR，
  不调用用户函数；不将框架内部故障伪装为业务失败。
- 正常返回 None 产生 SUCCESS；业务异常产生 TASK_ERROR，保存异常类型、摘要和 traceback。
  明确用户函数违反返回 None 契约时的框架错误行为。
- 超时使用单调计时；仅框架计时器触发才产生 TIMEOUT。
  用户函数自行抛出 TimeoutError 仍为 TASK_ERROR。
- 超时与外部取消必须遵守协作式取消：确认用户协程实际结束后才报告执行结束。
  明确外部取消的最终传递契约，不吞掉取消或提前释放执行资源。
  不响应取消的协程不得被当成已完成；不提供线程池或硬超时。
- EXECUTOR_ERROR 属于后续 Worker 级故障，明确错误边界，保留异常链；
  存储层没有此 ErrorKind，不写成 TASK_ERROR 或 CONFIG_ERROR。
- 使用标准库 logging 与 JSON formatter，记录时间、级别、事件、Job ID、尝试序号和错误类别；
  使用 contextvars 关联执行上下文，退出时恢复上下文，支持并发隔离。
  不默认记录完整参数，不捕获完整 stdout/stderr，不增加日志依赖。
- 只创建本任务实际使用的模型与模块，不预建 Worker、锁或 CLI。

不实现 Worker、重试决策与调度、进程锁、停机编排、崩溃恢复或 CLI；
执行器不在用户函数运行期间持有数据库会话。

## 必须验证的行为

使用真实 async 用户函数；事件或屏障控制并发和取消，不用固定长 sleep 同步：

- 参数按模型重新校验；正常返回、业务异常、未知名称和不匹配参数分类准确。
- 用户抛 TimeoutError 与框架超时明确区分；使用持久超时快照。
- 超时与外部取消等待用户协程真实退出，finally 能完成；
  受控的不响应取消场景在实际退出前不得提前报告完成，并在测试结束清理协程。
- 框架内部故障与业务错误分开，异常链保留，不自动重试。
- 错误类型、摘要与 traceback 足够支持存储接口；公共结果不可变。
- 实际 JSON 日志可解析、字段可关联；并发上下文互相隔离，结束后恢复，
  日志不泄露完整参数。
- 执行器不调用存储写接口；T02—T04 行为不回归。
- 依赖、uv.lock 与历史 T01 收据保持不变，不增加占位测试。
