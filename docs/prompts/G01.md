## 4. 认证、HTTP 与互斥基础

认证依次读取 GH_TOKEN、GITHUB_TOKEN，最后尝试 gh auth token --hostname github.com；
缺失凭据提供明确的非敏感诊断，供 G04 在 submit 前调用。
凭据只驻留内存，异常及异常链、日志、输入、数据库、缓存键和收据不包含 token。
取消时等待凭据子进程退出并回收。

使用 httpx.AsyncClient，固定 API 根地址、Accept 和计划选定版本。
实现计划的分项及单次请求总等待超时、每次尝试实际请求数与累计冷却等待预算。
生产遵循已有代理与证书环境；受控测试隔离这些环境，不依赖个人凭据或 GitHub 网络。
HTTP 层不额外自动重试，失败返回可诊断的业务原因供 TaskForge 有限重试使用。

实现分页及完整性检测：per_page=100、单列表默认最多 10 页；
缓存保存完整非敏感请求键、ETag、响应体与 Link，304 只复用对应缓存，
第一页 304 后仍核对后续页。无对应缓存、分页异常或预算耗尽时明确失败，不宣称完整。
分页与重定向请求保持 API 根地址约束，不把凭据发送到外部主机。

同一来源异步互斥与非阻塞文件锁，为后续完整采集及导出提供锁生命周期；锁文件保留。
同一业务实例共用 API 并发为 1 的请求门控，使用文件锁覆盖 Worker 与 direct 的进程。
请求前读取持久冷却；主限流、Retry-After 与二级限流的等待期限按计划持久化并取较晚值。
超过每次尝试等待预算则失败，冷却结束前后续尝试不发实际请求；换 token 不绕过冷却。
HTTP、数据库及凭据清理完成后才释放持有的锁，重复取消也不能提前释放资源。

完成条件：受控响应证明分页、304、超时、限流与预算处理；真实进程证明锁互斥、
请求串行及冷却跨重启生效；取消后无遗留子进程、HTTP 任务或数据库操作。

## 5. 必须验证与质量检查

行为测试覆盖以下内容，不能以对象构造成功替代真实资源验证：

- 配置未知字段、非法预算、重复 source_id、类型不相容、输入 JSON 往返及七来源默认值。
- 业务 schema 版本拒绝、重开、唯一身份、预算调整不重置基线、旧代次拒绝、事务回滚、
  记录与检查点同事务提交，以及 commit 结果不确定时从独立连接核对。
- 多页与缓存键隔离、304 复用原响应和 Link、第一页未变但后页变化、无缓存 304、
  分页/请求预算中断；失败不能推进业务检查点。
- 主/二级限流、Retry-After、等待期限合并、累计等待预算，以及新进程在冷却结束前
  实际请求数为零、换 token 仍遵守冷却。
- 同来源跨进程互斥、不同来源共用请求门控、锁文件保留、取消与重复取消期间不提前释放锁。
- 认证顺序与缺失诊断、HTTP 总等待超时、AsyncClient 关闭、数据库及凭据子进程取消清理；
  使用假的凭据检查敏感信息不进入异常链、日志和持久产物。

使用 httpx.MockTransport 或可控本地服务测试 HTTP，不启动七来源真实采集。
并发与故障验证使用事件或屏障；跨重启验证使用真实子进程及临时业务数据库，
不能仅在同一对象中模拟重新打开。全部子进程、连接与协程在 finally 中清理并等待结束。
历史验收记录了默认沙箱下 aiosqlite 跨线程通知挂起；按当前环境核验，
需要权限时使用现有审批机制，不修改核心驱动或事务语义绕过限制。
