### 会话交接与验收门槛

每个 G 任务由一个独立会话完成，按 G01 → G02 → G03 → G04 → G05 顺序交接。
G01、G02 已完成，下一独立会话使用 [G03 prompt](prompts/G03.md)；G04—G05 prompt 由前一任务验收通过后准备，
写明实际输入证据、允许修改范围、必要检查、完成标准及下一任务前置条件。
任务完成后停止，不在同一会话继续下一任务；Git Commit 由用户另行明确授权。

各任务读取项目 AGENTS.md 与其指定 skills，保留用户改动、历史 T01/T10 证据和核心公开接口。
新增依赖先形成声明与锁文件差异，确认安装后再同步环境，保留已有依赖版本。
检查采用新增行为测试和既有必要回归；实际命令、退出码、产物与限制记入
[verification.md](verification.md)，再同步本表及架构实现状态。
验收失败时留在当前任务修复，不以排期或已生成文件作为验收通过依据。

默认测试使用受控 API 与临时数据库，不依赖第三方凭据。真实 GitHub 验收独立显式执行；
七来源、重复刷新、历史重放及对照实验通过前，整体始终标为待验收。
初始化、自然更新、历史重放与故障实验分别统计；直接执行对照复用业务逻辑及请求门控，
使用固定本地输入和隔离数据库，不预设框架更快。详细证据要求见接入设计细则第 5 节。
